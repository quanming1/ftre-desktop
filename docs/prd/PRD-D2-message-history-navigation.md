## 1. 背景与目标

- **背景**：当前“会话目录”入口位于 Header 右上角，以展开式浮层显示用户消息。入口距离阅读区较远，切换上下文时不易发现，也无法持续表达当前所在位置。
- **目标**：将用户消息历史改为消息列表左侧中部的定位导航；用户可从纵向标记快速预览并跳转到任一已加载的用户消息，交互形态参考 Codex。
- **非目标**：本阶段不新建后端接口、不改变消息持久化或历史分页协议；未加载的更早消息仍由既有“从服务器加载更早的消息”流程加载。

## 2. 需求范围

### 2.1 功能需求

- [x] FR1：在会话消息列表左侧中部常驻展示当前会话所有已加载用户消息的纵向定位标记；消息加载更多后标记同步更新。
- [x] FR2：仅当鼠标悬停任一定位标记时，展示该用户消息标题及紧随其后的助手回复摘要；预览卡可承接指针，避免从标记移入卡片时意外消失。
- [x] FR3：悬停标记是唯一的视觉激活来源：被悬停标记向右展开，其余标记按与它的距离向上下逐级缩短，并有平滑过渡动画；离开整个导航后恢复为统一短标记。不得依据消息滚动位置自动计算或高亮当前项。
- [x] FR4：点击或按 Enter/Space 激活标记时，消息列表平滑定位到对应用户消息。
- [x] FR5：移除 Header 右上角旧“会话目录”按钮及其下拉浮层，保留 Header 的会话重命名和更多操作。
- [x] FR6：没有用户消息时不渲染导航；窄窗口时导航不遮挡消息正文，必要时隐藏预览卡而保留可访问的定位标记。

### 2.2 非功能需求

- 性能：悬停仅更新本地 UI 状态；不监听消息滚动、不为每个标记新增网络请求。
- 可访问性：定位标记是可聚焦按钮，具有可读的 `aria-label`；支持 Enter 与 Space 激活。
- 兼容性：复用现有 `msg-<id>` 锚点和历史分页，不改变 WebSocket、HTTP 或持久化结构。

## 3. 技术方案

- `ChatOutline.tsx` 由受 Header 控制的下拉目录调整为挂载在消息列表内的定位导航组件，复用用户消息提取和锚点跳转逻辑；仅维护 `hoveredId`，根据标记索引距离计算横向长度和透明度。
- `ChatMessageList.tsx` 为导航提供消息滚动容器；导航通过 Portal 挂到文档根节点并以 fixed 定位在列表左侧中部，避免 Workbench 的变换上下文改变坐标；预览卡锚定在标记右侧。
- `ChatHeader.tsx` 删除目录按钮、悬停定时器和浮层挂载，仅保留标题与更多操作。
- 预览卡的垂直中心对齐当前悬停标记；离开导航后清除 `hoveredId`，所有标记用 CSS transition 恢复为短横线。

## 4. 接口定义

- 不新增后端 API、IPC、WebSocket 事件或共享协议字段。
- 前端内部复用 `useChat` 的 `messages`、`sessionId`、`hasMoreHistory` 与 `useSession` 的 `loadEarlier(sessionId)`。

## 5. 验收标准

- [x] AC1：打开含多条用户消息的会话，消息列表左侧中部显示对应数量的定位标记，Header 不再显示会话目录图标。
- [x] AC2：仅悬停任一标记可看到对应消息的摘要；被悬停标记最长，邻近标记的横向长度按距离平滑递减；鼠标离开导航后全部恢复短横线。
- [x] AC3：点击或按 Enter/Space 后滚动到带有对应 `msg-<id>` 锚点的消息；滚动消息列表本身不得改变任何标记的激活状态；继续加载历史消息后导航内容随之更新。
- [x] AC4：空会话和窄窗口下不出现正文遮挡或控制台错误。
- [x] AC5：相关单元测试与 Renderer 生产构建通过。

## 6. 测试计划

- 单元测试：用户消息过滤、预览摘要、悬停时的距离递减长度、离开后的复位、点击锚点定位与键盘激活。
- 手动验证：创建多轮会话，悬停任意标记观察逐级长度动画、移入预览卡、离开导航、点击各标记；加载更早消息后再次验证导航；缩窄窗口检查预览卡与正文不重叠。
